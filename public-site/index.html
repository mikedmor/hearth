Features

Everything the house runs, in one place

Plain files on your own hardware. No account with anyone, no telemetry.

The start page

  • Sections and links with over 7,000 bundled logos, symbols and emoji
  • Live status for every service, checked every 30 seconds
  • Find services: scan the network; about 100 apps recognised
  • Ctrl+K to search and jump, and short links like start.home/plex

Everyone's own page

  • Who's here? Tap your face; a PIN keeps a page private
  • Roles: the admin, adults and children, each seeing what's meant for them
  • Your look: themes, layouts, backgrounds, fonts, even your own CSS
  • A set-up link that opens one person's page on a shared tablet

Widgets

  • Built in: service health, a family note, countdowns, clocks, your agenda
  • Ready-made for Plex, Jellyfin, Radarr, Pi-hole, Portainer, Nextcloud, Frigate and more
  • Your own from JSON, XML, RSS or WebSocket data
  • Live: one connection per page, updated as the data changes

Calendar

  • Everyone gets one, as a month, a week or a list, and a widget for the page
  • Add sources: Hearth's own, calendar links (.ics), CalDAV, and Google both ways
  • Share a whole calendar, or tag people on one event

AI, on your own server

  • Any Ollama or OpenAI-compatible server on your network
  • Chat for the roles you allow, with children's answers kept simple and safe
  • An AI designer that drafts a widget from a sentence and fixes it until it works

Private and safe

  • Plain files in one data folder: back it up with the rest of your NAS
  • Secrets encrypted with AES-256-GCM; passwords and PINs hashed
  • Nothing private for visitors: guests see only what's meant for everyone
  • No outbound calls unless you allow them, each one documented

Install

One container, a few commands

  1. You need Docker on any amd64 or arm64 machine, such as a NAS or a small home server.
  2. Run the commands, then open http://localhost:8082.
  3. The first visit asks for the setup code from docker logs hearth, then the admin password you choose.
  4. Keep a copy of .env somewhere safe. Its key encrypts widget keys and calendar sign-ins.
Install guide (Synology too) 
# a folder for Hearth and its data
mkdir -p hearth/data && cd hearth
git clone https://github.com/mikedmor/hearth.git src
cp src/docker/compose.yaml .

# the key that encrypts its secrets
umask 077; printf "HEARTH_SECRET_KEY=%s\n" "$(openssl rand -base64 32)" > .env

docker compose up -d --build

Google Calendar

How Hearth uses Google Calendar

When someone in a home connects their Google Calendar to Hearth, Google asks for a public page about the app and its privacy policy. This is that page. Hearth itself runs on the home's own server and can't be reached from here.

What Hearth asks Google for

  • See the list of your calendars, and the events in the ones you choose to show.
  • Add, change and delete events, only when you do so in Hearth.
  • Not your email, contacts, files or anything else, and never events from calendars you didn't choose.

Google's permission is stored encrypted on the home server and never shown on a page. Events are fetched when you look at your calendar and aren't copied anywhere else. You can disconnect at any time in Hearth, or at myaccount.google.com/permissions.

This website

Signing in with Google brings you back through this site's return page, which only sends your browser home to Hearth on your own network. The one-time code it passes along is useless without secrets only the home server has.

This site has no tracking, analytics, cookies, forms or outside scripts.

Hearth's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.
